# Т-Образование: Основы системного администрирования
## Лабораторная работа 1: NetQuest
Сервер: 153.76.167.185, на сервере работают пять сетевых сервисов на разных портах.

В каждом нужно написать программу-клиент, которая решит задачу и получит флаг: строку вида NQ{task_0123456789abcdef}.
В начале сессии сервер спрашивает ID. Введите свой ID: фамилию, латиницей, в нижнем регистре.
Флаг персональный: он вычисляется из вашего ID.
Каждое решенное задание даёт 1 балл, всего 5 баллов.
На платформе вы сдаете флаги и код ваших клиентов.
Сначала посмотрите на сервис руками: nc 153.76.167.185 <порт> (для UDP: nc -u).
Решить задания вручную не получится, нужна программа.

## 1. math — 7001/tcp
   Сервер присылает 100 арифметических примеров. На все нужно ответить за 30 секунд:

Q 1/100: 89 * 22 = ?

где / здесь целочисленное деление, % — остаток.

Ответ отправляется одним числом в строке.

## 2. bytes — 7002/tcp
   После строки BEGIN сервер присылает случайное количество случайных байт и делает паузы по ходу передачи.

Если сервер молчит 3 секунды, передача окончена.

Отправьте число байт, полученных после строки BEGIN\n.

Обрати внимние: один вызов recv() не равен одному send() на стороне сервера. Первая порция данных может прийти в одном recv вместе со строкой BEGIN.

Данные бинарные: в них встречаются любые байты, в том числе \n.

## 3. latency — 7003/tcp
   Сервер отвечает PONG <x> на каждый PING <x>. Задержка ответа складывается из двух частей: постоянной (у каждого студента своя) и случайного джиттера.

Джиттер всегда неотрицательный и иногда очень большой.

Определите постоянную часть с точностью ±5 мс и отправьте ANSWER <мс>.

Предварительно нужно сделать не меньше 20 замеров. На ответ даётся одна попытка за соединение.

Вопрос на подумать: какая характеристика выборки (среднее, медиана, минимум…) лучше всего подходит для этой оценки и почему? Сравните с выводом утилиты ping.

## 4. udp — 7004/udp (!)
   Отправьте датаграмму GET <ваш_id>. Сервер разрежет секретное сообщение на куски и пришлёт каждый отдельной датаграммой в формате:

<seq>/<total>|<данные>

где seq — номер куска, начиная с 0.

Около 30% датаграмм теряется, некоторые приходят дважды, порядок перемешан. Чтобы получить недостающие куски, отправьте RESEND <ваш_id> 3,7,12. Перезапрос тоже может потеряться. Соберите сообщение целиком, флаг находится внутри.

echo "GET <ID>" | nc -u -w1 153.76.167.185 7004

echo "RESEND <ID> 0,3" | nc -u -w1 153.76.167.185 7004

## 5. frames — 7005/tcp
   После ввода ID сервер присылает строку BINARY\n, и дальше общение идёт бинарными кадрами.

Все числа передаются в сетевом порядке байт (big-endian):

поле

размер

значение

magic

2 байта

всегда NQ (0x4E 0x51)

type

uint8

тип кадра

length

uint32

длина payload в байтах

payload

length

данные

Типы кадров:

1 QUESTION (от сервера): payload = op: uint8, n: uint16, затем n чисел int32. Операции:

1 - сумма

2 - максимум

3 - минимум

4 - XOR всех чисел.

2 ANSWER (от вас): payload = результат как int64 (8 байт).

3 NOISE (от сервера): мусор, такие кадры нужно пропускать.

4 RESULT (от сервера): текст UTF-8 с флагом.

5 ERROR (от сервера): текст UTF-8 с описанием ошибки.

Нужно пройти 30 раундов за 60 секунд.
